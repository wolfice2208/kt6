# «Протокол» — Fullstack React + TypeScript + FastAPI

Финальный проект по дисциплине «Разработка веб-приложений (React)», КТ 6.

Приложение мониторит аукцион игровых предметов, считает выгоду перепродажи с учётом
комиссии и расходов и ведёт личный журнал закрытых сделок с ROI, винрейтом и
динамикой по месяцам.

Главная идея проекта: **выгоду считает сервер**. Калькулятор отправляет параметры
сделки в `POST /api/trades/calculate`, а журнал считает те же величины по тем же
формулам. Одна формула на весь проект — цифры на экране калькулятора и в отчёте
не могут разойтись.

## Быстрый старт

Нужны только Python 3.9+ и Node.js 18+ в `PATH` — остальное скрипт поставит сам.

```bat
:: из корня проекта; так же работает двойной клик по файлу
запустить.cmd
```

```powershell
# то же самое напрямую из PowerShell
.\запустить.ps1
```

Скрипт создаёт `backend\.venv`, ставит зависимости (повторно — только если
изменился `requirements.txt`), подбирает свободные порты, прописывает адрес API
в `frontend\.env.local`, поднимает оба сервера в отдельных окнах, дожидается
ответа API и Vite и только после этого открывает браузер. Если порт занят,
берётся следующий свободный — какой именно, скрипт печатает в консоль.

Параметры (одинаковые для `.cmd` и `.ps1`):

```powershell
.\запустить.ps1 -BackendPort 8010 -FrontendPort 5180   # другие порты
.\запустить.ps1 -NoBrowser                             # не открывать браузер
.\запустить.ps1 -Reinstall                             # переставить зависимости
```

> **Если PowerShell пишет «выполнение сценариев отключено в этой системе»**
> (стандартная политика Windows — `Restricted`), запускайте `запустить.cmd`:
> он вызывает PowerShell с `-ExecutionPolicy Bypass` и ничего не меняет в системе.
> Альтернатива — один раз разрешить локальные скрипты:
>
> ```powershell
> Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
> ```

Серверы живут в двух отдельных окнах консоли: закрыть их — значит остановить
проект (в окнах видны и логи, и traceback, если что-то упало).

### Вручную

```powershell
# 1. Бэкенд
cd backend
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn main:app --host 127.0.0.1 --port 8000

# 2. Фронтенд (второй терминал)
cd frontend
npm install
npm run dev
```

Если бэкенд запущен не на 8000, укажите адрес в `frontend/.env`:

```
VITE_API_URL=http://127.0.0.1:8001/api
```

## Маршруты

| Маршрут | Доступ | Что делает |
|---|---|---|
| `/` | открыт | лента самых выгодных лотов + сводка рынка |
| `/catalog` | открыт | каталог 1000+ предметов: поиск, группа, сортировка, пагинация |
| `/catalog/:itemId` | открыт | карточка предмета: котировка, лоты, качество |
| `/calculator` | открыт | калькулятор выгоды (расчёт на сервере) |
| `/login` | открыт | форма входа, валидация, выдача JWT |
| `/trades` | **PrivateRoute** | журнал сделок: сводка, динамика, топ предметов |
| `/trades/:tradeId` | **PrivateRoute** | карточка сделки с полной раскладкой |
| `*` | открыт | страница 404 |

Два динамических маршрута (`useParams` с типом), два защищённых, отдельная 404.

## Ключевые решения

**Один паттерн асинхронности.** `AsyncState<T>` — дискриминированный union из четырёх
состояний (`idle | loading | success | error`). TypeScript не даёт прочитать `data`,
не проверив `status`. Компонент `AsyncView` рисует эти состояния одинаково везде,
поэтому «забыть про загрузку» технически неудобно.

**Один Axios-клиент.** `baseURL` берётся из `VITE_API_URL`, токен подставляет
request-interceptor, а response-interceptor ловит 401 и разлогинивает. Связь
«клиент ↔ стор» сделана через `bindAuth()`, чтобы не было циклического импорта.

**Три Zustand-хранилища.** Авторизация (с `persist`), фильтры каталога и поля
калькулятора. Фильтры и калькулятор не связаны с авторизацией — это требование
задания выполнено буквально.

**JWT по-настоящему.** Пароли хранятся как PBKDF2-HMAC-SHA256 с солью (стандартная
библиотека), токен — HS256 с `sub` и `exp`. Личные эндпоинты (`/trades`, `/filters`,
`/alerts`) без токена отдают 401, чужую запись нельзя прочитать — 404, а не 403,
чтобы не раскрывать существование id.

**Стилизация.** CSS Modules у каждого компонента и страницы; в глобальном файле
только палитра, типографика и сброс. Никакого смешивания подходов.

## Проверки

```powershell
# бэкенд: 50 тестов
cd backend
.\.venv\Scripts\python.exe -m pytest

# смоук API целиком (вход, каталог, калькулятор, журнал, изоляция пользователей)
.\.venv\Scripts\python.exe tools\smoke.py

# фронтенд: типы и сборка
cd frontend
npx tsc --noEmit
npm run build

# сквозная проверка в браузере (нужен запущенный бэкенд и dev-сервер)
npm i -D playwright
npx playwright install chromium
node scripts/verify-ui.mjs
```

Последний прогон `verify-ui.mjs`: 8 маршрутов, вход, расчёт `+24 315 ₽ / ROI +44.0 %`,
сохранение сделки, выход — **без ошибок в консоли и без упавших запросов**
(см. `docs/verify.log`).

## Настройки

Основное лежит в `backend/.env` (шаблон — `.env.example`):

| Переменная | Смысл |
|---|---|
| `DATA_SOURCE` | `mock` — синтетический рынок без сети; `demo`/`live` — реальный API |
| `ENABLE_INGESTION` | `false` — один обход при старте (цифры стабильны); `true` — воркер каждые 45 с |
| `FEE_PCT` | комиссия аукциона, по умолчанию 5 % |
| `JWT_SECRET` | секрет подписи; на проде обязательно переопределяется |
| `JWT_TTL_MINUTES` | время жизни токена, по умолчанию 4 часа |
| `CORS_ORIGINS` | адреса фронтенда через запятую |
| `SEED_DEMO_USERS` | создавать демо-пользователей при первом запуске |

Адрес API на фронтенде — `VITE_API_URL` в `frontend/.env` (шаблон `.env.example`).
